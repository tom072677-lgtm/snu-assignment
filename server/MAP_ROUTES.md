# 지도 경로 서비스

`mapRoutes.js`는 기존 세 경로 API의 응답 형식을 유지한다. 도보와 자동차는 TMAP을 우선 사용하고, 키가 없거나 요청·응답 검증이 실패하면 OSRM의 해당 이동수단 경로를 조회한다. 자전거는 OSRM을 사용한다. 셔틀 API의 기존 TMAP 보행 구간 보정은 변경하지 않는다.

응답의 `duration`은 초, `distance`는 미터, `path`는 `[위도, 경도]` 배열이다. `source`는 `TMAP` 또는 `OSRM`이며 `notice`에 예상시간의 한계를 안내한다. OSRM 자동차 결과는 실시간 교통을 반영한 시간으로 표시하면 안 된다. 출발·도착 좌표는 가까운 통행 가능한 길로 보정될 수 있다.

## OSRM 운영 조건

- 공식 운영 안내: https://routing.openstreetmap.de/about.html
- 운영자 제공 모드별 주소: https://github.com/fossgis-routing-server/osrm-frontend/blob/master/src/leaflet_options.js
- 유효한 앱 식별 User-Agent, 최대 초당 1회, 과도한 사용 금지, OpenStreetMap 출처 및 지도 수정 링크 표시가 요구된다. 앱의 경로 표시에서도 이 출처를 제공해야 한다.
- 서버 모듈은 모든 모드의 OSRM 요청을 한 큐에서 처리하고, 요청 시작 간격을 최소 1초로 둔다. 실행 중 요청을 포함해 최대 6개만 받으며 오래 대기한 요청은 거절한다. 동일 요청은 병합하고 성공 결과만 60초간 최대 100개 캐시한다.
- 큐·병합·캐시는 **한 Node 프로세스 범위**다. 복수 인스턴스나 다른 프로세스에서도 같은 공용 서비스를 사용하면 전체 호출 한도를 별도로 공유해야 한다. 현재 구조를 여러 인스턴스로 확장하기 전에 이 제한을 해결해야 한다.
- 외부 공개 서비스의 가용성과 지도 데이터 정확성을 보장하지 않는다. 실패 시 한국어 `error`와 `code`를 반환하며 임의의 직선거리 경로로 대체하지 않는다.

## 검증

네트워크 없는 회귀 테스트: `node --test server/mapRoutes.test.js`

2026-09-26에 기존 서버의 알림·DB를 시작하지 않고, 새 모듈만 별도 로컬 HTTP 서버에 연결해 공개 좌표 `(37.4607, 126.9526) → (37.4631, 126.9512)`로 무키 실제 조회를 확인했다.

| 이동수단 | 상태/출처 | 시간 | 거리 | 경로 좌표 수 |
|---|---|---|---|---|
| 도보 | 200 / OSRM | 277.4초 | 346.7m | 15 |
| 자전거 | 200 / OSRM | 232.7초 | 438.3m | 19 |
| 자동차 | 200 / OSRM | 66초 | 272.9m | 10 |

이는 로컬 모듈과 외부 경로 API의 실행 확인이며 운영 서버 배포 확인은 아니다. 운영 반영에는 서버 배포가 필요하다.
